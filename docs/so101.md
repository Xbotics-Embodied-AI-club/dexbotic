# SO101 单臂：用 DM0.5 与 DW0.5 做抓放

本文说明怎样在 SO101 单臂（5 个关节 + 1 个夹爪）上微调 DM0.5（VLA 策略）与
DW0.5（world-action 世界模型），并在仿真里评测。可导入的部分在 `dexbotic.so101` 包里：
训练配置与入口 `dexbotic.so101.dm05_exp` / `dexbotic.so101.dw05_exp`，目录约定 `layout`，
DW0.5 推演自检 `dw05_sim_check`，开环自检 `openloop_check`，数据转换 `lerobot_v3_to_dexdata`。
`script/so101/` 放多卡训练与评测的 shell 流水线；`playground/` 下同名入口保留为转发。

单卡上的一套入口（工作坊教学仓 Xbotics-Dexmal-Workshop 的讲义就按这套走），都用 `python -m dexbotic.so101.<名字>` 运行：

| 入口 | 作用 |
| --- | --- |
| `download` | 下载发布的权重（`--weights`）与训练数据（`--data`），版本钉死 |
| `serve` | 起 DM0.5 推理服务（默认发布的权重，`--checkpoint` 换成自己的） |
| `rollout` | DM0.5 驱动 SO-101 抓放。机器人用 LeRobot 的配置写法给出（`--robot.type=so101_sim` 或 `so101_follower` …），仿真与真机同一个控制循环 |
| `label_videos` | 给 rollout 录像加上来历与成败横幅 |
| `imagine` | DW0.5 按 rollout 的真实轨迹推演未来，并与两个参照对比 |
| `prepare_data` | 仿真三场景 + 真机九任务转成一份 dexdata |
| `train_lora` | 单卡 LoRA 微调 DM0.5（300 步现场配方），训完做开环自检 |

`rollout` 需要 LeRobot：`so101-sim` 附加项会把 Xbotics 维护的 LeRobot 与仿真器一起装上。

## 目录约定与环境变量

所有落点由一个根目录推出，定义只在 `dexbotic/so101/layout.py` 一处；训练入口
与各脚本都从那里取默认值，每一项都可以用同名环境变量单独覆盖。

```
$SO101_ROOT/                        默认 ~/so101_workspace
├── datasets/                       SO101_DATASETS_DIR
│   ├── so101-sim-640-v2/           仿真数据：cube40 / cube20 / cylinder40
│   ├── so101-real/                 真机数据：九个任务，每个一个子目录
│   └── so101-dexdata/              转换产物：jsonl/ 与 text_embeddings/
├── weights/                        SO101_WEIGHTS_DIR
│   ├── DM05/                       DM0.5 底座
│   ├── DW05-Robotwin/              DW0.5 底座（DW05_BUNDLE）
│   └── DW05-Robotwin-noactionhead/ 剔掉机器人专属权重后的起点
└── runs/                           SO101_RUNS_ROOT
    ├── dm05_so101/                 DM0.5 存点与归一化统计
    ├── dw05_so101/                 DW0.5 存点与归一化统计
    └── logs/                       run_pipeline.sh 的日志
```

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `SO101_ROOT` | `~/so101_workspace` | 工作区根目录 |
| `SO101_DATASETS_DIR` | `$SO101_ROOT/datasets` | 数据根；dexdata 里视频 url 相对它 |
| `SO101_WEIGHTS_DIR` | `$SO101_ROOT/weights` | 权重根 |
| `SO101_RUNS_ROOT` | `$SO101_ROOT/runs` | 训练产物根 |
| `DW05_BUNDLE` | `$SO101_WEIGHTS_DIR/DW05-Robotwin` | DW0.5 底座目录 |
| `SO101_SHM_ROOT` | `/dev/shm/so101` | `stage_to_shm.sh` 搬数据与权重的 tmpfs 目录 |
| `PY` | `python` | 训练侧解释器 |
| `SIM_PY` | 无，必填 | 仿真侧解释器（评测时用） |
| `LEROBOT_PY` | 无，必填 | 装了 lerobot 的解释器（对齐校验时用） |

卡号一律由调用方给：训练脚本读 `CUDA_VISIBLE_DEVICES`，`run_pipeline.sh` 读
`DM_GPUS` / `DW_GPUS`，评测脚本读第四个参数与 `SIM_GPUS`。

## 两个环境

仿真（ManiSkill/SAPIEN，torch 2.8）与 Dexbotic 训练（torch 2.11 + transformers 5.3 +
deepspeed）装不进同一个环境，两边只通过 checkpoint 文件与 HTTP 推理服务交接。

训练侧，在仓根：

```bash
uv sync
export PY=$PWD/.venv/bin/python
```

仿真侧，在 `script/so101/sim_env/`（so101_sim 按 commit 从 GitHub 装，torch 钉在 2.8.0，
驱动需支持 CUDA 12.8）：

```bash
cd script/so101/sim_env
uv sync
export SIM_PY=$PWD/.venv/bin/python
```

对齐校验（`verify_dexdata_alignment.py`）拿 lerobot 自己的数据集 API 解帧当真值，
需要一个装了 `lerobot` 与 `av` 的环境，用 `LEROBOT_PY` 指过去。

## 数据与权重

训练数据是两份公开数据集，共 3698 集：

| 数据集 | 版本 | 内容 | 放到 |
| --- | --- | --- | --- |
| HF `Harrysunshine/so101-sim-pickplace-v2` | `92ca801c` | 仿真，取 `cube40` / `cube20` / `cylinder40` 三个子目录，1498 集 | `$SO101_DATASETS_DIR/so101-sim-640-v2/` |
| ModelScope `zhuzhuangtian/so101-pick-place-tasks` | `f64493c4` | 真机，九个任务，2200 集 | `$SO101_DATASETS_DIR/so101-real/` |

```bash
# 一个场景一次：同一条命令里给多个 --include，实测只取回了其中两个子目录，且不报错。
for scene in cube40 cube20 cylinder40; do
  hf download Harrysunshine/so101-sim-pickplace-v2 --repo-type dataset \
    --revision 92ca801c614cda2481029122b75ed20c72f39495 \
    --include "$scene/*" --local-dir "$SO101_DATASETS_DIR/so101-sim-640-v2"
done

modelscope download --dataset zhuzhuangtian/so101-pick-place-tasks --revision f64493c4 \
  --local_dir "$SO101_DATASETS_DIR/so101-real"
```

仿真目录名里写着分辨率（640×480）：分辨率不一致既不报错也不影响收敛，名字里写死
能让拿错版本在 `ls` 那一刻就看得见。

权重：

```bash
hf download Dexmal/DM05 --local-dir "$SO101_WEIGHTS_DIR/DM05"
hf download Dexmal/DW05-Robotwin --local-dir "$DW05_BUNDLE"
# DW0.5 的底座 DiT 不在发布包里，放进包内约定的位置（同样一个 --include 一次）
for pattern in "*.json" "*.safetensors"; do
  hf download Wan-AI/Wan2.2-TI2V-5B --include "$pattern" \
    --local-dir "$DW05_BUNDLE/Wan-AI/Wan2.2-TI2V-5B"
done
```

DM0.5 要 dexbotic 布局的 `Dexmal/DM05`，不是 lerobot 布局的 `DM05-Lerobot`。

## 一条龙：从数据到开训

数据与权重就位后，在仓根：

```bash
DM_GPUS=0,1 DW_GPUS=2,3,4 LEROBOT_PY=<装了 lerobot 的 python> STAGE_SHM=1 \
  bash script/so101/run_pipeline.sh
```

`run_pipeline.sh` 依次做：

1. 数据验收：任务数 / 集数 / 帧数与上表两个版本逐项相等，全部视频都是 640×480；
2. `convert_all.sh`：两份数据转进同一份 dexdata；
3. `verify_dexdata_alignment.py`：仿真、真机各抽一个来源，逐像素确认画面与动作没有错位；
4. `precompute_text_embeds.py`：DW0.5 的文本嵌入缓存；
5. `strip_robot_specific_weights.py`：从 DW05-Robotwin 剔掉机器人专属权重（产物已在就跳过）；
6. （`STAGE_SHM=1` 时）`stage_to_shm.sh` 把数据搬进内存，并把 DW0.5 权重顺序拷进内存；
7. DW0.5 归一化统计；
8. `setsid` 并行起两个训练，日志在 `$SO101_RUNS_ROOT/logs/{dm05,dw05}.log`。

`DM_GPUS` 给 4 张卡时每卡 8 凑不出等效 batch 48，再加 `PER_DEVICE=6`。
`PREP_GPU` 指定第 4、7 步用的卡，默认 `DW_GPUS` 的第一张。

## 每一步单独跑

| 步骤 | 命令（仓根） | 环境 |
| --- | --- | --- |
| 转 dexdata | `bash script/so101/convert_all.sh` | 训练侧 |
| 对齐校验 | `$LEROBOT_PY script/so101/verify_dexdata_alignment.py --dexdata $SO101_DATASETS_DIR/so101-dexdata --lerobot $SO101_DATASETS_DIR/so101-sim-640-v2/cube20 --repo-id local/sim_cube20 --name sim_cube20` | lerobot |
| 文本嵌入 | `$PY script/so101/precompute_text_embeds.py --jsonl-dir $SO101_DATASETS_DIR/so101-dexdata/jsonl --out $SO101_DATASETS_DIR/so101-dexdata/text_embeddings --bundle $DW05_BUNDLE` | 训练侧 |
| 校验文本嵌入 | `$PY script/so101/verify_text_embeds.py --cache ... --bundle $DW05_BUNDLE --prompt "<a>" --prompt "<b>"` | 训练侧 |
| 剔权重 | `$PY script/so101/strip_robot_specific_weights.py --in $DW05_BUNDLE/model.pt --out $SO101_WEIGHTS_DIR/DW05-Robotwin-noactionhead/model.pt` | 训练侧 |
| 搬内存（可选） | `bash script/so101/stage_to_shm.sh` | 任意 |
| DW0.5 归一化 | `CUDA_VISIBLE_DEVICES=0 bash script/so101/train_dw05_so101.sh compute_norm_stats` | 训练侧 |
| DW0.5 训练 | `CUDA_VISIBLE_DEVICES=0,1,2 bash script/so101/train_dw05_so101.sh train trainer_config.resume=$SO101_WEIGHTS_DIR/DW05-Robotwin-noactionhead/model.pt` | 训练侧 |
| DM0.5 训练 | `CUDA_VISIBLE_DEVICES=0,1 bash script/so101/train_dm05_so101.sh` | 训练侧 |

两个入口的覆盖语法不同：DM0.5 是 `tyro`，写 `--trainer-config.num-train-steps 5000`；
DW0.5 是 dotlist，写 `trainer_config.max_steps=20000`（不带 `--`，必须有 `=`）。

## 训练配方

| | DM0.5 | DW0.5 |
| --- | --- | --- |
| 方式 | LoRA | 全量微调 + DeepSpeed ZeRO-1 |
| 起点 | `Dexmal/DM05` | `DW05-Robotwin` 剔掉动作头与本体编码器后的权重 |
| batch | 等效 48（`卡数 × 每卡 × 累积`，累积步数由脚本按卡数现算） | 每卡 1 |
| 步数 | 5000（每 1000 步存一次） | 20000（每 10000 步存一次，每 200 步 eval 一次） |
| 动作口径 | `ActionMode.RELATIVE` | 从相邻帧状态现算 delta，夹爪维不做 delta |

DW0.5 的状态排布：SO101 的 6 维填进 RobotWin 16 槽里第一臂的前五槽与夹爪槽，第二臂留空；
视图用 top + wrist + wrist 拼成预训练见过的三路布局。

## 仿真评测

DM0.5，三个场景各起一个推理服务与一个仿真进程并行：

```bash
SIM_PY=$SIM_PY SIM_GPUS=3,4,5 bash script/so101/eval_dm05_so101.sh \
  $SO101_RUNS_ROOT/dm05_so101/checkpoint-5000 50 <输出目录> 0,1,2
```

- 每场景 50 局，成功取环境自己的 `is_success`（物体落在料箱范围内、手臂不碰物体、手臂不碰料箱、机器人静止）；
- 判据：三个场景的 Clopper-Pearson 95% 下界都 > 70%（50 局时至少 42 局成功）；
- 每个动作块执行 25 步再重新请求（`REPLAN`，默认 25）；
- 结果写 `<输出目录>/summary.json`，每局的 top / wrist 视频与逐步状态在各场景的 `videos/`。

`python -m dexbotic.so101.openloop_check` 在训练数据上做开环自检，闭环成功率很低时用它分清「没学会」
与「推理链配错」。

DW0.5 在训练集外的仿真轨迹上验证：用上面 DM0.5 评测存下的轨迹，
比较照真动作推演的未来画面与两个基线（复制首帧、时序翻转的动作）：

```bash
CUDA_VISIBLE_DEVICES=0 $PY -m dexbotic.so101.dw05_sim_check \
  --checkpoint <DW0.5 存点> --rollout-dir <评测输出>/cube40 --out <目录>
```

判据：真动作的平均 PSNR 同时高于两个基线，且逐条轨迹上真动作胜过翻转的占多数。
`dw05_policy_server.py` 把 DW0.5 的动作专家包成与 DM0.5 同契约的 HTTP 服务，
可以用同一个 `rollout_so101.py` 量它的成功率。

## 参考结果

DM0.5，5000 步，每场景 50 局：

| 场景 | 成功 | 95% 下界 |
| --- | --- | --- |
| cube40 | 47/50 | 83.5% |
| cube20 | 47/50 | 83.5% |
| cylinder40 | 46/50 | 80.8% |

DW0.5，训练集外 12 条仿真轨迹上的平均 PSNR：真动作 21.46 dB，复制起始帧 17.43 dB，
倒放动作 16.66 dB（从第 1 帧起计分；轨迹取自发布的 DM0.5 验收时存下的局），逐条比较真动作胜翻转 12/12。

## 已知坑

**动作口径。** DM0.5 按 RELATIVE 训练，但推理服务的输出变换已经把状态加回去、返回绝对角，
所以评测 harness 用 `--action-mode absolute`。按 relative 再加一次状态会让目标角约成两倍，
不报错，只表现为很低的成功率。`rollout_so101.py` 的 `--action-mode` 没有默认值，必须写明。

**DW0.5 的本体状态训练时不归一化。** 训练的 `norm_stats.json` 只有 `action`，本体状态直接
取排布后的原始角度。上游 policy 按 RobotWin 的习惯会对状态做分位数归一化，照搬就是喂给
模型一个训练时没见过的量纲。`dw05_sim_check.py` 的 `patch_policy_for_so101` 把这一步换成
与训练一致，`dw05_policy_server.py` 也用它。

**共用 GPU 可能渲出黑块。** 与别的作业共用的卡可能渲出成片纯黑像素，策略看到的是训练里
没有的脏图，成功率被压低且不报错。评测渲染放在单独的卡上（`SIM_GPUS`）；
`rollout_so101.py` 在每个场景的首帧自检，纯黑像素超过 1000 就退出。
